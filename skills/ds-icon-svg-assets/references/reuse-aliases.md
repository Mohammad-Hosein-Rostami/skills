# Reuse aliases — why name matching is not the check

PascalCasing an `IceIconsEnum` key does **not** tell you whether the glyph already exists.
`TRASH` is the existing `Delete`. `PENCIL` is `Edit`. `CHECK_CIRCLE` is `CircleCheck` with the words
reversed. And `INFO_CIRCLE` is **not** the existing `Info`, even though the names look compatible.

So the `todo` / `reuse` column in `docs/icon-refactor-inventory.md` is a **name-level** signal only.
Before creating any file, run the geometry check:

```bash
pnpm icons:match temp/icons/<glyph>.svg
```

This table is the shortlist of candidates to check first. It does not replace the check.

## Rotation, not a new file

One chevron and one arrow cover four directions. Check whether the Figma glyph is a rotation of what
we have before adding a near-duplicate file:

| Enum key                 | Base component | Transform                                                                                                               |
| ------------------------ | -------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `CHEVRON_UP`             | `ChevronDown`  | Prefer dedicated **`ChevronUp`** when Figma ships `ice- Arrow Up` (MI Report). Rotate only if measure matches           |
| `CHEVRON_LEFT`           | `ChevronDown`  | Prefer dedicated **`ChevronLeft`** when Figma ships `ice - Arrow Left` (filled chevron). Rotate only if measure matches |
| `CHEVRON_RIGHT`          | `ChevronDown`  | Prefer dedicated **`ChevronRight`** when Figma ships `ice- Arrow right`. Rotate only if measure matches                 |
| `ARROW_RIGHT`            | `ArrowLeft`    | Prefer new `ArrowRight` when Figma `ice-Right arrow` fails rotate match (`0%` vs `ArrowLeft`)                           |
| `ARROW_UP`, `ARROW_DOWN` | `ArrowLeft`    | `rotate(90deg)` / `rotate(-90deg)`                                                                                      |

Apply it at the call site, not inside the icon:

```tsx
<DsIcon customIcon={<ChevronDown />} size={11} sx={{ transform: 'rotate(-90deg)' }} />
```

**Caveat:** only valid when Figma's glyph really is the same artwork rotated. Directional glyphs are
often redrawn with different optical corrections — a rotated chevron whose stroke caps differ will
fail the pixel diff. Measure, do not assume. If Figma ships a distinct drawing, create the file.

**CTA colour:** `ArrowRight` on a contained primary button needs `color="iceGray.50"` (or
`inherit !important`). Untinted `DsIcon` defaults dark grey and disappears on blue CTAs
(“Go to Call” / “Rejoin”). Outlined Call buttons use `color="primary.500"`.

`libraries/shared/designSystem/src/materio/@core/theme/overrides/autocomplete.tsx:24` renders
`icon="DOWN_CHEVRON"`, and `DOWN_CHEVRON` is not a key in `iceIconsEnum.ts`. That icon renders

## Reserved-name collisions

`libraries/shared/assets/images/icons/` already exports `Download`, `Upload`, `CheckBox`
and ~45 more. Those are the multi-colour illustration set, not DsIcon glyphs. Needing
`UPLOAD` as a monochrome DsIcon glyph means creating a **new** file in `icons/` and disambiguating
the name, the way `DownloadIcon` / `UploadIcon` already do. Full list in `icon-catalog.md`.

### Resolved by migration, not by suffixing

`Calendar`, `Lock`, and `Unlock` were on that reserved list. They now exist as tintable glyphs in `icons/`, and
the barrel's `./images/icons/Calendar`, `./images/icons/Lock` and `./images/icons/Unlock` lines were **deleted** rather than
kept alongside. The illustration files still sit on disk in `images/icons/`, but only `icons/` is exported for those
names. **Exception:** `CalendarGold` (navbar active gold gradient) still lives in `images/icons/Calendar.tsx` and is
re-exported selectively as `export { CalendarGold } from './images/icons/Calendar'` so it does not collide with tintable
`Calendar`.

That is the preferred resolution when the illustration has no live call site: migrate and drop the
old export. Suffixing (`DownloadIcon`) is the fallback for when the illustration is still in use.
Before adding a suffix, check whether the `images/icons/` version is actually referenced anywhere.

### MUI collisions

The other namespace to check is `@mui/material`. `IceList` and `IceEmojiPlus` carry the `Ice` prefix
for exactly this reason, matching the Figma layer names `ice-List` / `ice-Grid`.

`Grid` is the one that got away: it collides with MUI `Grid`, which `mui-layout-grid` requires for
every multi-column layout and which appears in ~90 files. Any file needing both must alias
`import { Grid as GridIcon } from '@ice-web-app/assets'`. Do not repeat this — a new glyph whose
natural name is an MUI export gets the `Ice` prefix.

## Two-tone illustrations are not reuse candidates

The 35 Choose-a-Symbol glyphs (`Solar`, `Robotics`, `Biotech`, `Partner`, …) bake a semantic tone
pair and render bare rather than through `DsIcon`. Never reuse one as a UI glyph: it will not respond
to `color`, and it is sized for an 88px card. Conversely, never satisfy a Choose-a-Symbol slot with a
tintable UI glyph — it will render flat where the design expects strong + tint artwork.

The `Category*` tabs are the exception inside that feature: they are ordinary tintable glyphs and
follow the normal rules. See `color-conventions.md`.
